# Контрольная работа №4. JavaScript: интерактивность, DOM, события, формы и валидация

## Цель

Проверить умение студента добавить интерактивность в учебный интернет-магазин с использованием чистого JavaScript.

В результате студент должен: подготовить репозиторий `kr4-js-shop`, создать массив товаров, реализовать генерацию карточек через JS, поиск, фильтрацию, сортировку, базовую валидацию формы, безопасный вывод через `textContent`, обработчики через `addEventListener()`, описать логику в README.md.

## Требования к данным (`js/data.js`)

```javascript
const products = [
  { id: 1, title: 'Название', category: 'category', price: 1000, isAvailable: true }
];
```

- 8–12 товаров; одинаковая структура; уникальные `id`; цены — числа; категории совпадают с фильтром.
- ❌ `price: '1000'` → ✅ `price: 1000`

## Требования к каталогу (`catalog.html`)

Работают: вывод карточек, поиск, фильтр, сортировка, пустое состояние, счётчик найденных.

- Поиск реагирует на `input`; фильтр — на `change`.
- Сортировку применять к копии: `[...products].sort((a, b) => a.price - b.price)`.
- Не писать карточки вручную в HTML.

## Требования к генерации карточек

```javascript
const container = document.querySelector('.product-list');
container.innerHTML = '';
products.forEach(product => {
  const card = document.createElement('div');
  card.classList.add('product-card');
  const title = document.createElement('h3');
  title.textContent = product.title;
  card.appendChild(title);
  container.append(card);
});
```

## Требования к безопасному выводу

Для пользовательских данных, формы, `localStorage`, API — **без `innerHTML`**:

```javascript
element.textContent = userInput;
```

`innerHTML` допустим только для статической контролируемой разметки.

## Требования к событиям

```javascript
element.addEventListener('click', handler);
element.addEventListener('input', handler);
element.addEventListener('change', handler);
form.addEventListener('submit', handler);
```

Не использовать inline-обработчики `<button onclick="...">`.

## Требования к валидации (`order.html`)

- Пустая форма не проходит; проверка e-mail и телефона; ошибки рядом с полями; сообщения на страницу; без `alert()`; сообщение об успешной подготовке заявки.
- Сложная валидация не требуется — достаточно базовой клиентской проверки.

## Проверка консоли

Открыть DevTools → Console. Критических ошибок быть не должно на всех страницах. Если скрипт ищет элемент, которого нет на странице, добавить проверку:

```javascript
if (element) { /* работа */ }
```

## Типичные ошибки

| Ошибка | Почему | Как исправить |
|---|---|---|
| Проект с пустой страницы | Не понята связь с предыдущими КР | Создать на основе интернет-магазина |
| Меньше 8 товаров | Только учебный массив | Расширить до 8–12 |
| Карточки в HTML вручную | Не выполнена генерация через JS | `createElement()` |
| Поиск только после перезагрузки | Нет обработчика `input` | `addEventListener('input', ...)` |
| Фильтр не работает | Категории не совпадают | Сверить `product.category` и `option value` |
| Сортировка ломает порядок | `sort()` на исходном массиве | Сортировать копию `[...arr]` |
| Ошибки через `alert()` | Старый подход | Вывод в DOM через `textContent` |
| `innerHTML` для пользовательских данных | Безопасность | `textContent`, `createElement`, `append` |
| Скрипт падает на другой странице | Ищет несуществующий элемент | Проверка `if (element)` |
| README без описания JS | Документация не обновлена | Добавить описание файлов и функций |
| Студент не объясняет код | Код скопирован | Разобрать функции и сценарии |

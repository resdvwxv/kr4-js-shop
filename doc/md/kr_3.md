
# Контрольная работа №3

## Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта

Это принципиально важно, потому что Bootstrap уже содержит готовую адаптивную сетку и готовые адаптивные компоненты. В КР №3 студент должен показать самостоятельное владение:
* медиазапросами;
* Flexbox;
* CSS Grid;
* responsive images;
* адаптивными формами;
* адаптивными таблицами;
* основами доступности.

### 3. Что сдаётся по контрольной работе

Студент сдаёт отдельный репозиторий:
```text
kr3-responsive-shop/
├── index.html
├── catalog.html
├── product.html
├── order.html
├── contacts.html
├── css/
│   ├── style.css
│   └── responsive.css
├── js/
│   └── main.js
├── images/
├── lighthouse/
│   └── accessibility-report.png
├── README.md
└── .gitignore
```

Файл `js/main.js` допускается, если он использовался в КР №1 для базового открытия и закрытия модального окна. Основная оценка КР №3 связана не с JavaScript, а с адаптивностью и доступностью.

В СДО сдаётся контрольная работа в виде ссылки на итоговый репозиторий.

Если проект опубликован через GitHub Pages, ссылка на опубликованную версию должна быть указана в `README.md`.

### 6. Требования к подключению CSS

На каждой HTML-странице должны быть подключены стили:
```html
<link rel="stylesheet" href="css/style.css"> 
<link rel="stylesheet" href="css/responsive.css">
```

Это нужно, чтобы адаптивные правила могли переопределять базовые стили проекта.

Проверьте подключение на страницах:
* `index.html`;
* `catalog.html`;
* `product.html`;
* `order.html`;
* `contacts.html`.

### 7. Требования к viewport

На каждой HTML-странице в `head` должен быть тег:
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

Если `viewport` отсутствует, мобильный браузер может отображать сайт как уменьшенную desktop-страницу.

### 8. Требования к адаптивности

Проект необходимо проверить минимум на следующих ширинах:

| Устройство / режим | Пример ширины |
| :--- | :--- |
| Мобильный экран | 360px |
| Мобильный экран крупнее | 430px |
| Планшет | 768px |
| Небольшой desktop | 1024px |
| Широкий desktop | 1440px |

На каждой ширине необходимо проверить:
* шапку;
* навигацию;
* hero-блок;
* сетку карточек;
* страницу каталога;
* боковой фильтр;
* страницу товара;
* таблицу характеристик;
* форму заявки;
* контакты;
* подвал;
* модальное окно, если оно используется.

### 9. Требования к отсутствию горизонтального скролла

На мобильной ширине не должно быть горизонтального скролла всей страницы.

Если горизонтальный скролл есть, необходимо проверить:
* фиксированные ширины блоков;
* таблицы;
* изображения;
* длинные слова;
* карточки товаров;
* модальное окно;
* fixed/sticky-элементы.

Нельзя считать нормальной ситуацию, когда вся страница прокручивается вбок. Горизонтальная прокрутка допускается только внутри специально заданного контейнера, например `.table-wrapper` для широкой таблицы.

### 10. Требования к responsive images

Изображения не должны выходить за пределы контейнеров.

В CSS должно быть правило:
```css
img, video { 
  max-width: 100%; 
  height: auto; 
}
```

Минимум для одного блока изображений должны быть использованы `srcset`, `sizes` или `picture`.

Пример:
```html
<img src="images/product-1-640.jpg" 
     srcset="images/product-1-480.jpg 480w, images/product-1-640.jpg 640w, images/product-1-960.jpg 960w" 
     sizes="(max-width: 639px) 100vw, (max-width: 1023px) 50vw, 33vw" 
     alt="Учебный товар" 
     width="640" 
     height="480" 
     loading="lazy" 
>
```

Рекомендуется проверить через вкладку Network в DevTools, какие изображения загружаются на разных ширинах.

### 11. Требования к адаптивным формам

Форма заявки должна быть удобной на мобильном экране.

Необходимо проверить:
* поля не выходят за границы экрана;
* поля имеют `label`;
* поля достаточно крупные для нажатия;
* кнопки не слипаются;
* на мобильном экране форма идёт в одну колонку;
* на планшете и desktop допускается двухколоночная структура.

### 12. Требования к адаптивным таблицам

Таблица характеристик не должна ломать ширину страницы.

Допустимый базовый вариант — обернуть таблицу в контейнер с горизонтальной прокруткой:
```html
<div class="table-wrapper"> 
  <table class="product-table"> 
    <!-- ... --> 
  </table> 
</div>
```

Пример CSS:
```css
.table-wrapper { 
  overflow-x: auto; 
  -webkit-overflow-scrolling: touch; 
} 

.product-table { 
  width: 100%; 
  min-width: 640px; 
}
```

Если студент сделал карточное представление таблицы на мобильном экране, это может считаться самостоятельной доработкой.

### 13. Требования к доступности

В проекте необходимо проверить:
* на каждой странице есть один `h1`;
* заголовки идут в логичном порядке;
* навигация размечена через `nav`;
* ссылки и кнопки используются по назначению;
* видимый фокус есть на всех интерактивных элементах;
* у полей формы есть `label`;
* у изображений есть осмысленные `alt`;
* контраст текста достаточный;
* модальное окно доступно для клавиатуры;
* ARIA используется только при необходимости.

### 14. Требования к Lighthouse

Необходимо проверить минимум следующие страницы:
* `index.html`;
* `catalog.html`;
* `order.html`.

В Lighthouse нужно выбрать категорию Accessibility.

После проверки необходимо сохранить отчёт или скриншот в папку `lighthouse/`.

Пример:
```text
lighthouse/
└── accessibility-report.png
```

Допускается сохранить HTML-отчёт:
```text
lighthouse/
└── accessibility-report.html
```

### 22. Типичные ошибки при сдаче КР №3

| Ошибка | Почему возникает | Как исправить |
| :--- | :--- | :--- |
| Адаптируется Bootstrap-проект из КР №2 | Студент перепутал основу КР №3 | Использовать HTML/CSS-проект из КР №1 |
| Нет отдельного репозитория | Работа выполнена внутри КР №1 | Создать `kr3-responsive-shop` |
| Нет `responsive.css` | Все стили добавлены в основной CSS без структуры | Создать и подключить отдельный файл |
| Нет `viewport` | Мобильная версия отображается некорректно | Добавить `meta viewport` |
| Медиазапросы написаны случайно | Нет понимания Mobile First | Сначала написать мобильную версию, затем расширять |
| Есть горизонтальный скролл всей страницы | Широкий элемент выходит за экран | Найти элемент через DevTools и исправить |
| Таблица ломает мобильную версию | Нет адаптации таблицы | Использовать `.table-wrapper` или карточное представление |
| Форма неудобна на телефоне | Поля стоят в несколько узких колонок | На мобильном сделать одну колонку |
| Изображения выходят за контейнер | Нет `max-width: 100%` | Добавить базовое правило для изображений |
| Lighthouse-отчёт есть, но ошибки не исправлены | Отчёт сделан формально | Исправить найденные проблемы и повторить проверку |
| README не описывает адаптивные решения | README скопирован из предыдущей КР | Добавить разделы по адаптивности, доступности и Lighthouse |

В JavaScript-блоке используется проектный паттерн:

```
Данные → функции обработки → состояние интерфейса → рендер в DOM → события → обновление состояния → повторный рендер

```

Итоговая логика каталога:

1. В `data.js` хранится массив товаров.

## 5. Краткая теория

### 5.1. Что такое DOM

DOM — это объектная модель документа. Когда браузер загружает HTML-страницу, он превращает её в дерево объектов.

Например, HTML-разметка:

```html
<main>
  <h1>Каталог</h1>
  <section>
    <h2>Товары</h2>
  </section>
</main>
```

В JavaScript становится набором объектов, к которым можно обращаться:

- найти заголовок;
- изменить текст;
- добавить карточку товара;
- удалить элемент;
- повесить обработчик события;
- изменить CSS-класс.

DOM нужен для того, чтобы JavaScript мог управлять HTML-страницей.

### 5.2. Поиск элементов на странице

Чтобы изменить элемент, его сначала нужно найти.

Основные способы:

```javascript
document.getElementById('catalog-search');
document.querySelector('.products-grid');
document.querySelectorAll('.product-card');
```

В данном проекте рекомендуется использовать `querySelector`, потому что он работает с CSS-селекторами и позволяет искать элементы так же, как они описываются в CSS.

Пример:

```javascript
const productsContainer = document.querySelector('[data-products-container]');
```

Здесь ищется элемент с атрибутом `data-products-container`.

Преимущество такого подхода: JavaScript меньше зависит от визуальных CSS-классов. Класс можно поменять для оформления, а `data-*`-атрибут оставить как точку подключения JavaScript.

### 5.3. Безопасное изменение текста

Для вывода текста используйте `textContent`.

Пример:

```javascript
const messageElement = document.querySelector('.catalog-message');

messageElement.textContent = 'Найдено 5 товаров.';
```

`textContent` выводит строку как обычный текст.

Не используйте `innerHTML` для данных, которые пришли:

- из формы;
- из поля поиска;
- из `localStorage`;
- из адресной строки;
- из будущего API;
- из внешнего источника.

Плохо:

```javascript
messageElement.innerHTML = userInput;
```

Лучше:

```javascript
messageElement.textContent = userInput;
```

Причина: `innerHTML` воспринимает строку как HTML-разметку. Если в строке окажется вредоносная разметка, это может стать уязвимостью. В учебном проекте закрепляется безопасный паттерн: пользовательские данные выводятся как текст.

### 5.4. Создание элементов через JavaScript

Чтобы создать карточку товара, можно использовать `document.createElement()`.

Пример:

```javascript
const titleElement = document.createElement('h3');
titleElement.classList.add('product-card__title');
titleElement.textContent = product.title;
```

Пояснение:

- `createElement('h3')` создаёт заголовок;
- `classList.add()` добавляет CSS-класс;
- `textContent` безопасно записывает текст.

После создания элемент нужно добавить в другой элемент:

```javascript
cardElement.append(titleElement);
```

Такой подход лучше, чем сборка всей карточки через большую строку `innerHTML`, потому что текстовые данные не интерпретируются как HTML.

### 5.5. Работа с CSS-классами через `classList`

`classList` позволяет управлять классами элемента.

Примеры:

```javascript
element.classList.add('is-active');
element.classList.remove('is-hidden');
element.classList.toggle('is-open');
```

В проекте это нужно для:

- показа и скрытия сообщений;
- открытия и закрытия модального окна;
- изменения состояния кнопки;
- отображения пустого состояния каталога;
- переключения темы как самостоятельной доработки.

### 5.6. Атрибуты `data-*`

Атрибуты `data-*` позволяют хранить технические данные в HTML.

Пример:

```html
<button type="button" data-action="add-to-cart" data-product-id="3">
  В корзину
</button>
```

В JavaScript значение можно получить так:

```javascript
const productId = Number(button.dataset.productId);
```

В данном проекте `data-product-id` пригодится для кнопки «В корзину» или «Подробнее».

Даже если корзина не является обязательной частью базового уровня, такой паттерн полезно понимать заранее.

### 5.7. События

Событие — это действие, которое произошло на странице.

Примеры событий:

| Событие | Когда происходит |
|---------|------------------|
| `click` | пользователь нажал на кнопку |
| `input` | пользователь вводит текст |
| `change` | пользователь изменил значение `select` |
| `submit` | пользователь отправил форму |
| `keydown` | пользователь нажал клавишу |

Обработчик события подключается через `addEventListener()`:

```javascript
searchInput.addEventListener('input', (event) => {
  console.log(event.target.value);
});
```

Пояснение:

- `searchInput` — поле поиска;
- `input` — событие ввода;
- `event.target.value` — текущее значение поля;
- функция выполняется каждый раз, когда пользователь вводит текст.

### 5.8. Почему не используем `onclick` в HTML

Плохо:

```html
<button onclick="addToCart(1)">В корзину</button>
```

Лучше:

```html
<button type="button" data-action="add-to-cart" data-product-id="1">
  В корзину
</button>
```

```javascript
button.addEventListener('click', () => {
  addToCart(1);
});
```

Причины:

- HTML отвечает за структуру;
- CSS отвечает за внешний вид;
- JavaScript отвечает за поведение;
- код легче поддерживать;
- обработчики можно подключать к элементам, созданным динамически;
- проект становится ближе к реальной frontend-разработке.

### 5.9. Делегирование событий

Если карточки товаров создаются через JavaScript, кнопки внутри карточек тоже создаются динамически.

Можно повесить обработчик на каждую кнопку отдельно. Но удобнее использовать делегирование событий: повесить один обработчик на общий контейнер.

Пример:

```javascript
productsContainer.addEventListener('click', (event) => {
  const button = event.target.closest('[data-action="add-to-cart"]');

  if (!button) {
    return;
  }

  const productId = Number(button.dataset.productId);
  console.log(productId);
});
```

Пояснение:

- обработчик висит на контейнере;
- `closest()` ищет ближайшую кнопку с нужным атрибутом;
- если клик был не по кнопке, выполнение прекращается;
- если кнопка найдена, берётся `data-product-id`.

Такой подход удобен для каталога, где карточки могут перерисовываться после поиска, фильтрации и сортировки.

### 5.10. Состояние интерфейса

Состояние интерфейса — это текущие значения, от которых зависит отображение страницы.

Для каталога состояние может выглядеть так:

```javascript
const catalogState = {
  query: '',
  category: 'all',
  sort: 'default'
};
```

Пояснение:

- `query` — поисковая строка;
- `category` — выбранная категория;
- `sort` — выбранный способ сортировки.

Когда пользователь меняет поле поиска, категорию или сортировку, состояние обновляется, а каталог перерисовывается.

### 5.11. Рендер

Рендер — это вывод данных на страницу.

В данной работе рендер означает:

- очистить контейнер товаров;
- подготовить список товаров с учётом поиска, фильтра и сортировки;
- создать карточки товаров;
- добавить карточки в DOM;
- показать количество найденных товаров;
- показать пустое состояние, если товаров нет.

### 5.12. Базовая валидация формы

Валидация формы — это проверка введённых данных.

В данной работе используется базовая клиентская валидация:

- проверка пустых полей;
- проверка e-mail;
- проверка телефона;
- вывод сообщений об ошибках на страницу;
- предотвращение отправки формы через `preventDefault()`.

Сложные схемы валидации, библиотеки и компонентная архитектура форм будут рассматриваться позже в блоке React/Vue.

Пример обработчика формы:

```javascript
form.addEventListener('submit', (event) => {
  event.preventDefault();

  const isValid = validateForm();

  if (!isValid) {
    return;
  }

  console.log('Форма прошла проверку');
});
```

### 5.13. Отладка JavaScript

Для поиска ошибок используйте:

- вкладку Console;
- `console.log()`;
- `console.table()`;
- `console.warn()`;
- вкладку Sources;
- Breakpoints.

Breakpoint позволяет остановить выполнение кода на конкретной строке и посмотреть значения переменных.

Типовой порядок отладки:

1. Открыть DevTools.
2. Перейти во вкладку Console.
3. Посмотреть текст ошибки.
4. Найти файл и строку ошибки.
5. Перейти во вкладку Sources.
6. Поставить breakpoint.
7. Повторить действие на странице.
8. Проверить значения переменных.

#### 1. Один DOM-элемент

DOM — дерево объектов страницы. `querySelector()` ищет существующий контейнер, `createElement()` создаёт новый узел в памяти, `textContent` задаёт безопасный текст, а `append()` помещает узел на страницу. Предскажите: появится ли текст до `append()`?

```javascript
{
  const list = document.querySelector('#lab-list');
  const note = document.createElement('p');
  note.textContent = 'Карточка готова';
  console.log(list.children.length); // 0
  list.append(note);
  console.log(list.children.length); // 1
}
```

#### 9. Телефон: форматирование отдельно от проверки

```javascript
{
  const phone = document.querySelector('#lab-form [name="phone"]');
  function digitsOf(value) {
    const digits = value.replace(/\D/g, '');
    if (digits === '') return '';
    return digits.startsWith('8') ? `7${digits.slice(1)}`
      : digits.startsWith('7') ? digits : `7${digits}`;
  }
  function isPhoneValid(value) {
    const digits = digitsOf(value);
    return digits.length === 11 && digits.startsWith('7');
  }
  function formatPhone(value) {
    const digits = digitsOf(value);
    if (!digits) return '';
    const visible = digits.slice(0, 11);
    const extra = digits.slice(11);
    const part = visible.slice(1);
    return '+7' + (part ? ` (${part.slice(0, 3)}` : '')
      + (part.length >= 3 ? ')' : '')
      + (part.length > 3 ? ` ${part.slice(3, 6)}` : '')
      + (part.length > 6 ? `-${part.slice(6, 8)}` : '')
      + (part.length > 8 ? `-${part.slice(8, 10)}` : '')
      + (extra ? ` [лишние цифры: ${extra}]` : '');
  }
  phone.addEventListener('input', () => { phone.value = formatPhone(phone.value); });
  console.log(isPhoneValid('')); // false
  console.log(isPhoneValid('8 999 123')); // false
  console.log(isPhoneValid('8 999 123-45-67')); // true
  console.log(isPhoneValid('8 999 123-45-678')); // false
}
```

Предскажите результаты для пустого, неполного, полного и слишком длинного номера. `digitsOf()` сохраняет все содержательные цифры; `isPhoneValid()` отдельно проверяет их количество. Маска меняет только вид поля: лишние цифры остаются видимыми после номера и приводят к ошибке, а не исчезают при обрезке. Введите, вставьте и удалите цифры; проверьте все четыре случая. Этот первый опыт намеренно показывает проблему курсора при редактировании середины: он прыгает в конец. Самостоятельно восстановите позицию по количеству цифр слева от курсора, используя `selectionStart` и `setSelectionRange()` из принятого учебного проекта; проверьте замену средней цифры, вставку и удаление. Не считайте наличие скобок доказательством корректности номера.

### Этап 8. Функции подготовки данных

Добавьте функции из предыдущего занятия или перенесите их из `main.js`.

```javascript
function searchProducts(products, query) {
  const normalizedQuery = query.trim().toLowerCase();

  if (normalizedQuery === '') {
    return products;
  }

  return products.filter((product) => {
    return product.title.toLowerCase().includes(normalizedQuery);
  });
}

function filterProductsByCategory(products, category) {
  if (category === 'all') {
    return products;
  }

  return products.filter((product) => {
    return product.category === category;
  });
}

function sortProducts(products, sortType) {
  const productsCopy = [...products];

  if (sortType === 'price-asc') {
    return productsCopy.sort((a, b) => a.price - b.price);
  }

  if (sortType === 'price-desc') {
    return productsCopy.sort((a, b) => b.price - a.price);
  }

  if (sortType === 'title-asc') {
    return productsCopy.sort((a, b) => a.title.localeCompare(b.title));
  }

  return productsCopy;
}

function getPreparedProducts(products, state) {
  let result = [...products];

  result = searchProducts(result, state.query);
  result = filterProductsByCategory(result, state.category);
  result = sortProducts(result, state.sort);

  return result;
}
```

Пояснение:

- каждая функция отвечает за одну задачу;
- функции можно комбинировать;
- `sortProducts` сортирует копию массива, а не исходный массив;
- `getPreparedProducts` применяет поиск, фильтр и сортировку последовательно.

## 14. Типичные ошибки

| Ошибка | Почему возникает | Как исправить |
|--------|------------------|---------------|
| Карточки не выводятся | Не найден контейнер товаров | Проверить `data-products-container` и подключение `catalog.js` |
| В консоли ошибка `products is not defined` | `data.js` не подключён или подключён позже `catalog.js` | Подключить `data.js` перед `catalog.js` |
| Поиск не работает | Не обновляется `catalogState.query` | Проверить обработчик `input` |
| Фильтр не работает | Значения `option value` не совпадают с `product.category` | Привести значения к единому виду |
| Сортировка ломает исходный порядок | `sort` применяется к исходному массиву | Сортировать копию через `[...products]` |
| Карточки дублируются | Контейнер не очищается перед рендером | Использовать `productsContainer.textContent = ''` |
| Пустое состояние не показывается | Не проверяется длина массива | Проверить `productsToRender.length` |
| Используется `innerHTML` для названия товара | Студент собирает карточку строкой | Использовать `createElement` и `textContent` |
| Обработчики не срабатывают на новых карточках | Обработчики повешены до создания элементов | Использовать делегирование событий |
| Форма отправляется и перезагружает страницу | Не используется `preventDefault()` | Добавить `event.preventDefault()` |
| Ошибки формы выводятся через `alert()` | Студент копирует старые примеры | Выводить ошибки в элементы формы через `textContent` |
| После исправления поля ошибка не исчезает | Нет обработчика `input` | Добавить проверку при вводе |
| Код падает на другой странице | Скрипт ищет элементы, которых нет на странице | Добавить проверки `if (element)` |
| README не обновлён | Студент сделал только код | Описать структуру JS и реализованные функции |

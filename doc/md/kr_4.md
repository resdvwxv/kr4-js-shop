# Контрольная работа №4. JavaScript: интерактивность, DOM, события, формы и валидация

## 1. Цель контрольной работы

Цель контрольной работы №4 — проверить умение студента добавить интерактивность в учебный интернет-магазин с использованием чистого JavaScript.

В результате выполнения контрольной работы студент должен:

- подготовить отдельный репозиторий kr4-js-shop;
- использовать в качестве основы ранее разработанный интернет-магазин;
- создать массив товаров;
- реализовать генерацию карточек товаров через JavaScript;
- реализовать поиск по названию товара;
- реализовать фильтрацию по категории;
- реализовать сортировку по цене или названию;
- реализовать базовую валидацию формы;
- выводить ошибки и сообщения на страницу без использования alert() как основного способа уведомления;
- использовать безопасный вывод данных через textContent;
- применять querySelector, createElement, classList, append;
- подключать обработчики событий через addEventListener();
- оформить структуру JavaScript-файлов;
- описать реализованную логику в README.md;
- подготовить ссылку на репозиторий для сдачи в СДО.

## 2. Общая логика контрольной работы

Контрольная работа №4 продолжает общую линию дисциплины.

| Контрольная работа | Что создаётся |
|---|---|
| КР №1 | интернет-магазин на HTML/CSS |
| КР №2 | отдельная версия интернет-магазина на Bootstrap или альтернативном CSS-фреймворке |
| КР №3 | адаптивная версия интернет-магазина из КР №1 |
| КР №4 | интерактивная версия интернет-магазина на JavaScript |
| КР №5 | SPA-версия интернет-магазина на React или Vue |

Рекомендуемая основа для КР №4 — проект КР №3 `kr3-responsive-shop`, потому что он уже содержит адаптивную версию HTML/CSS-интернет-магазина.

Допускается использовать собственный проект КР №1 или Bootstrap-проект из КР №2 как альтернативу, но студент должен понимать, что основная логика КР №4 проверяет JavaScript, DOM, события, формы, данные и безопасность вывода, а не возможности Bootstrap.

## 5. Требования к данным

В `js/data.js` должен быть массив товаров:

```javascript
const products = [
  {
    id: 1,
    title: 'Название товара',
    category: 'category',
    price: 1000,
    isAvailable: true
  }
];
```

Требования к массиву:

- товаров не менее 8;
- желательно не более 12 для учебной работы;
- у всех товаров одинаковая структура;
- категории совпадают со значениями в фильтре;
- id уникальны;
- цены записаны числами, а не строками.

Некорректный вариант:

```javascript
price: '1000'
```

Корректный вариант:

```javascript
price: 1000
```

## 7. Требования к генерации карточек

Карточки товаров должны создаваться средствами JavaScript.

Рекомендуемый подход:

- найти контейнер карточек через querySelector;
- очистить контейнер перед новым выводом;
- пройти по массиву товаров;
- для каждого товара создать DOM-элементы через createElement;
- заполнить текстовые данные через textContent;
- добавить классы через classList;
- добавить карточку в контейнер через append.

Не рекомендуется писать все карточки вручную в HTML.

## 8. Требования к поиску, фильтрации и сортировке

В проекте должны быть реализованы:

- поиск по названию товара;
- фильтрация по категории;
- сортировка по цене или названию.

Поиск должен реагировать на ввод пользователя через событие input.

Фильтр должен реагировать на изменение значения через событие change.

Сортировку рекомендуется применять к копии массива, чтобы не нарушать исходный порядок данных.

Пример идеи:

```javascript
const sortedProducts = [...products].sort((a, b) => a.price - b.price);
```

## 9. Требования к форме и валидации

На странице `order.html` должна работать базовая валидация формы.

Необходимо проверить:

- пустая форма не проходит проверку;
- e-mail проверяется;
- телефон проверяется;
- ошибки выводятся рядом с полями или в понятном блоке;
- сообщения выводятся на страницу;
- не используется alert() как основной способ сообщения;
- после корректного заполнения появляется сообщение об успешной подготовке заявки.

Сложная валидация форм не требуется в КР №4. Достаточно показать базовую клиентскую проверку и корректную работу с DOM.

## 10. Требования к безопасному выводу данных

Для пользовательских данных, данных формы, данных из localStorage и будущих API-данных не должно использоваться небезопасное вставление через innerHTML.

Рекомендуемый паттерн:

```javascript
const title = document.createElement('h3');
title.textContent = product.title;
```

Или:

```javascript
messageElement.textContent = 'Заявка подготовлена.';
```

Если innerHTML используется для статической, полностью контролируемой разметки, студент должен понимать ограничение и уметь объяснить, почему там нет пользовательских данных. В базовом учебном решении лучше обходиться без innerHTML.

## 11. Требования к событиям

В проекте должны использоваться обработчики:

```javascript
element.addEventListener('click', handler);
element.addEventListener('input', handler);
element.addEventListener('change', handler);
form.addEventListener('submit', handler);
```

Не рекомендуется использовать inline-обработчики в HTML:

```html
<button onclick="addToCart()">...</button>
```

Правильнее держать поведение в JavaScript-файлах.

## 14. Самостоятельные доработки КР №4

Для получения оценки выше 4 баллов студент должен добавить самостоятельные доработки.

Самостоятельная доработка должна быть осмысленной, связанной с интерфейсом интернет-магазина и объяснённой в README.md.

Базовое сообщение об отсутствии найденных товаров обязательно. Как самостоятельная доработка учитывается расширенное оформление пустого состояния или дополнительные действия в нём.

Возможные самостоятельные доработки:

| Доработка | Что проверяет |
|---|---|
| Корзина | работа с массивом выбранных товаров |
| Расчёт суммы корзины через reduce | расчёты и методы массивов |
| Скидка или промокод | условия, функции, пересчёт суммы |
| Избранное | отдельное состояние интерфейса |
| localStorage | сохранение корзины, избранного или темы |
| Пагинация | работа с подмножеством массива |
| Счётчик товаров | обновление состояния интерфейса |
| Расширенное оформление пустого состояния каталога | оформление и дополнительные действия сверх обязательного сообщения об отсутствии найденных товаров |
| Имитация отправки формы | завершённый пользовательский сценарий |
| Тёмная тема | classList, состояние, сохранение выбора |
| Улучшенная карточка товара | дополнительные поля, рейтинг, бейджи, состояние наличия |
| Модальное окно товара | события, доступность, вывод данных |
| Расширенная валидация формы | дополнительные правила без перегруза архитектуры |

Простая замена названий товаров, цветов или текста без расширения JavaScript-логики не считается существенной самостоятельной доработкой.

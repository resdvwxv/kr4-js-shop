## 5. Краткая теория

### 5.1. Что такое JavaScript

JavaScript — это язык программирования, который используется в браузере для добавления поведения на веб-страницу.

HTML задаёт структуру страницы.

CSS задаёт внешний вид страницы.

JavaScript задаёт поведение страницы.

В проекте интернет-магазина JavaScript нужен для следующих задач:

* поиск товаров;
* фильтрация товаров по категории;
* сортировка товаров по цене или названию;
* вывод карточек товаров на страницу;
* открытие и закрытие модального окна;
* обработка формы заявки;
* проверка введённых данных;
* вывод сообщений пользователю;
* добавление товара в корзину;
* расчёт суммы заказа;
* сохранение данных в `localStorage`.

В данной практической работе JavaScript используется сначала в простом виде: для описания товара, расчёта цены и проверки подключения скриптов.

### 5.2. Где выполняется JavaScript

В рамках данной дисциплины JavaScript выполняется в браузере.

Проверять код можно:

* через консоль браузера;
* через HTML-страницу;
* через отдельные `.js`-файлы, подключённые к HTML;
* через DevTools.

Консоль браузера нужна для отладки. Это инструмент разработчика, а не основная форма сдачи работы.

В контрольной работе №4 основная форма результата — репозиторий с HTML, CSS, JavaScript-файлами, `README.md`, историей коммитов и рабочей демонстрацией проекта.

### 5.3. Подключение JavaScript к HTML

JavaScript подключается к HTML через тег `script`.

Для учебного проекта используйте внешний JavaScript-файл:

```html
<script src="js/data.js" defer></script>
<script src="js/main.js" defer></script>
```

Атрибут `defer` означает, что браузер загрузит скрипт, но выполнит его после того, как HTML-документ будет разобран.

Это важно, потому что JavaScript часто обращается к элементам страницы. Если скрипт выполнится слишком рано, нужные элементы ещё могут не существовать.

Порядок подключения файлов также важен.

Если `main.js` использует переменные из `data.js`, сначала подключается `data.js`, а потом `main.js`:

```html
<script src="js/data.js" defer></script>
<script src="js/main.js" defer></script>
```

Если порядок перепутать, в консоли может появиться ошибка:

```text
product is not defined
```

Это означает, что код пытается использовать переменную, которая ещё не была создана.

### 5.4. Консоль браузера

Консоль браузера открывается через DevTools.

На занятии она используется для проверки:

* подключился ли файл JavaScript;
* есть ли ошибки;
* правильно ли создан объект товара;
* правильно ли работают функции;
* какие значения хранятся в переменных.

**Основные команды:**

```js
console.log('Обычное сообщение');
console.warn('Предупреждение');
console.error('Ошибка');
console.table({ title: 'Товар', price: 1000 });
```

**Пример:**

```js
const productTitle = 'Кофемашина';
console.log(productTitle);
```

**Пояснение:**

* создаётся переменная `productTitle`;
* в неё записывается строка `'Кофемашина'`;
* значение выводится в консоль.

### 5.5. Почему `prompt()` и `alert()` не являются основой проектной работы

В JavaScript существуют команды:

```js
alert('Сообщение');
prompt('Введите значение');
```

Их можно использовать для быстрой демонстрации, но они плохо подходят для реального интерфейса интернет-магазина.

**Причины:**

* `alert()` блокирует страницу до закрытия окна;
* `prompt()` не связан с реальной HTML-формой;
* такие окна нельзя нормально стилизовать через CSS;
* они не дают нормальный пользовательский сценарий;
* они плохо подходят для валидации форм и сообщений на странице.

В проекте интернет-магазина пользователь будет вводить данные через HTML-форму, а сообщения будут выводиться в специальные блоки на странице.

**Пример блока сообщения:**

```html
<p class="js-message" aria-live="polite"></p>
```

**Пример вывода сообщения:**

```js
const messageElement = document.querySelector('.js-message');
messageElement.textContent = 'JavaScript подключён корректно.';
```

Такой подход ближе к реальной frontend-разработке.

### 5.6. Переменные

Переменная — это имя для хранения значения.

В современных учебных проектах используются `const` и `let`.

`const` используется, если значение не должно переназначаться:

```js
const shopName = 'Учебный интернет-магазин';
```

`let` используется, если значение будет изменяться:

```js
let cartCount = 0;
cartCount = cartCount + 1;
```

`var` — старый способ объявления переменных. В новых работах его лучше не использовать, потому что у него менее очевидная область видимости, и начинающие чаще допускают с ним ошибки.

**Практическое правило:**

* используйте `const` по умолчанию;
* используйте `let`, если значение действительно будет изменяться;
* не используйте `var` в новых учебных проектах.

### 5.7. Типы данных

Тип данных определяет, какое значение хранится в переменной и какие действия с ним можно выполнять.

В проекте интернет-магазина будут использоваться следующие типы:

| Тип | Пример | Где используется |
| --- | --- | --- |
| `string` | `'Кофемашина'` | название товара, категория, сообщение |
| `number` | `19990` | цена, скидка, количество |
| `boolean` | `true` | товар в наличии или нет |
| `null` | `null` | значения пока нет |
| `undefined` | `undefined` | значение не задано |
| `object` | `{ title: 'Товар' }` | товар, заявка, пользователь |
| `array` | `[product1, product2]` | список товаров, корзина |

Пример:

```js
const title = 'Кофемашина';
const price = 19990;
const isAvailable = true;
```

Пояснение:

* `title` хранит строку;
* `price` хранит число;
* `isAvailable` хранит логическое значение.

### 5.8. Объект товара

Объект — это структура данных, которая хранит набор свойств.

В интернет-магазине товар удобно описывать объектом:

```js
const product = {
  id: 1,
  title: 'Кофемашина Barista Home',
  category: 'kitchen',
  price: 19990,
  discountPercent: 10,
  rating: 4.7,
  isAvailable: true
};
```

Пояснение:

* `id` — уникальный идентификатор товара;
* `title` — название товара;
* `category` — категория;
* `price` — цена;
* `discountPercent` — скидка в процентах;
* `rating` — рейтинг;
* `isAvailable` — наличие товара.

Получить значение свойства можно через точку:

```js
console.log(product.title);
console.log(product.price);
```

В следующей практической работе один объект будет заменён массивом товаров.

### 5.9. Арифметические операторы

Арифметические операторы используются для расчётов.

| Оператор | Назначение | Пример |
| --- | --- | --- |
| `+` | сложение | `price + deliveryPrice` |
| `-` | вычитание | `price - discount` |
| `*` | умножение | `price * count` |
| `/` | деление | `price / 2` |
| `%` | остаток от деления | `count % 2` |

Пример расчёта скидки:

```js
const price = 19990;
const discountPercent = 10;
const discountValue = price * discountPercent / 100;
const finalPrice = price - discountValue;
console.log(finalPrice);
```

Пояснение:

* `discountValue` хранит размер скидки;
* `finalPrice` хранит итоговую цену.

### 5.10. Операторы сравнения

Операторы сравнения возвращают `true` или `false`.

| Оператор | Назначение |
| --- | --- |
| `>` | больше |
| `<` | меньше |
| `>=` | больше или равно |
| `<=` | меньше или равно |
| `===` | строго равно |
| `!==` | строго не равно |

Пример:

```js
const price = 1999;
console.log(price > 10000);
console.log(price === 19990);
console.log(price !== 0);
```

В новых проектах лучше использовать строгое сравнение `===`, а не `==`.

Причина: `===` не выполняет неявное преобразование типов, поэтому результат проверки более предсказуем.

### 5.11. Логические операторы

Логические операторы используются для объединения условий.

| Оператор | Назначение |
| --- | --- |
| `&&` | логическое И |
| `||` | логическое ИЛИ |
| `!` | логическое НЕ |

Пример:

```js
const price = 19990;
const isAvailable = true;
const canBuy = price > 0 && isAvailable;
console.log(canBuy);
```

Пояснение:

* товар можно купить, если цена больше нуля и товар есть в наличии;
* если хотя бы одно условие ложно, `canBuy` будет `false`.

### 5.12. Условный оператор `if`

Условный оператор позволяет выполнить код только при определённом условии.

```js
const isAvailable = true;

if (isAvailable) {
  console.log('Товар доступен для заказа');
} else {
  console.log('Товара нет в наличии');
}
```

В интернет-магазине условия нужны для:

* проверки наличия товара;
* проверки скидки;
* проверки заполнения формы;
* вывода разных сообщений пользователю;
* проверки состояния корзины;
* проверки выбранной категории фильтра.

### 5.13. Функции

Функция — это блок кода, который можно вызвать несколько раз.

Функции нужны, чтобы не повторять один и тот же код в разных местах проекта.

Пример:

```js
function formatPrice(price) {
  return `${price} руб.`;
}

console.log(formatPrice(19990));
```

**Пояснение:**

* `formatPrice` — имя функции;
* `price` — параметр функции;
* `return` возвращает результат;
* при вызове `formatPrice(19990)` функция вернёт строку `'19990 руб.'`.

В проекте функции нужны для:

* форматирования цены;
* расчёта скидки;
* проверки наличия товара;
* подготовки текста карточки;
* проверки формы;
* расчёта суммы корзины.

### 5.14. Область видимости

Область видимости определяет, где доступна переменная.

Пример:

```js
const productTitle = 'Кофемашина';

function printProductTitle() {
  const message = `Название товара: ${productTitle}`;
  console.log(message);
}

printProductTitle();
```

Здесь:

* `productTitle` создана снаружи функции и доступна внутри неё;
* `message` создана внутри функции и доступна только внутри этой функции.

Пример ошибки:

```js
function createMessage() {
  const message = 'Привет';
}

console.log(message);
```

Такой код вызовет ошибку, потому что `message` существует только внутри функции.

Практическое правило:

* не создавайте лишние глобальные переменные;
* храните связанные данные в объектах;
* выносите повторяющуюся логику в функции;
* называйте переменные по смыслу.

### 5.15. Безопасный вывод данных на страницу

В JavaScript можно вставлять данные на страницу разными способами.

Небезопасный подход:

```js
const userText = '<img src=x onerror=alert(1)>';

const messageElement = document.querySelector('.js-message');
messageElement.innerHTML = userText;
```

Проблема в том, что `innerHTML` воспринимает строку как HTML-разметку. Если строка пришла от пользователя, из формы, из адресной строки, из `localStorage` или в будущем из API, в ней может оказаться вредоносная разметка.

Более безопасный подход:

```js
const userText = '<img src=x onerror=alert(1)>';

const messageElement = document.querySelector('.js-message');
messageElement.textContent = userText;
```

`textContent` выводит строку как обычный текст, а не как HTML.

В учебном проекте используется правило:

* для пользовательских данных используйте `textContent`;
* для значений полей формы используйте `value`;
* для создания элементов используйте `document.createElement()`;
* для добавления и удаления классов используйте `classList`;
* не используйте `innerHTML` для данных, которые может изменить пользователь.

Этот паттерн будет особенно важен в следующих практиках, когда товары будут выводиться на страницу, а форма заявки будет получать пользовательские данные.

### Эксперимент: переменная, тип и свойство

Предскажите значения трёх строк Console, затем запустите блок отдельно. `let` допускает новое присваивание, а `const` сохраняет ссылку на объект, хотя его свойство можно изменить.

```js
{
  const item = { title: 'Лампа', price: 1200, isAvailable: true };
  let amount = 1;
  amount += 1;
  item.price = 1100;
  console.log(amount);                 // 2
  console.log(typeof item.price);     // "number"
  console.log(item.title, item.price); // Лампа 1100
}
```

Измените `item.price` на строку `'1100'`. Снова предскажите `typeof` и объясните, почему значение с цифрами теперь не является числом. Для чтения значения из поля или `dataset` используйте пример преобразования в разделе «Типы данных» лекции: проверьте отдельно `Number('1100')`, `Number('abc')` и пустую строку. Некорректный ввод нельзя молча считать ценой.

### Эксперимент: строка → число

Поле формы и `dataset` возвращают строки. Сначала предскажите три результата, затем выполните весь блок в Console. Проверка пустой строки нужна отдельно: `Number('')` даёт `0`, хотя цену пользователь не ввёл.

```js
{
  const samples = ['1100', 'abc', ''];
  for (const raw of samples) {
    const value = Number(raw);
    const valid = raw.trim() !== '' && Number.isFinite(value);
    console.log(raw, value, valid);
  }
}
```

Проверьте после запуска: `'1100'` → `1100`, `true`; `'abc'` → `NaN`, `false`; `''` → `0`, `false`.

### Эксперимент: выражение и ветвление

До запуска определите, какая ветвь выполнится и чему равна `finalPrice`. Выполните блок в Console.

```js
{
  const price = 1000;
  const discountPercent = 10;
  const isAvailable = true;
  const finalPrice = price - price * discountPercent / 100;
  if (isAvailable && finalPrice < price) {
    console.log('Товар доступен со скидкой', finalPrice); // 900
  } else {
    console.log('Скидка недоступна');
  }
}
```

Сначала вычисляется `finalPrice = 900`; оба условия дают `true`, поэтому видна первая строка. Поменяйте `isAvailable` на `false`, затем отдельно скидку на `0`. В обоих опытах предскажите новую ветвь. Самостоятельно добавьте `else if` для случая «товар есть, но скидки нет» и проверьте все три состояния.

### Эксперимент: параметр, return и область видимости

Сначала предскажите результат обеих строк Console. Вызов функции получает аргумент `500`, локальная переменная `discount` существует только во время работы функции, а `return` отдаёт вычисленное число.

```js
{
  function discountedPrice(price, percent) {
    const discount = price * percent / 100;
    return price - discount;
  }
  const result = discountedPrice(500, 20);
  console.log(result);                  // 400
  console.log(discountedPrice(500, 0)); // 500
}
```

Измените процент на `25` и проверьте ожидаемые `375`. Затем в отдельном запуске временно замените `return price - discount` на `console.log(price - discount)` и проверьте, что переменная `result` стала `undefined`. Верните `return`. Не обращайтесь к `discount` снаружи функции: локальное имя там недоступно. Теперь самостоятельно напишите пять функций из задания и для каждой запишите вход и ожидаемый выход до запуска.

Проверка перед проектом: объясните тип каждой переменной, почему пустая строка не является корректной ценой, какую ветвь выбирает условие и чем `return` отличается от `console.log`. Затем выполните проектные этапы ниже самостоятельно.

### Этап 13. Демонстрация небезопасного подхода

Этот пример нужен только для понимания. Не используйте его как основной код проекта.

```js
const unsafeExample = '<img src=x onerror=alert(1)>';

// Небезопасно для пользовательских данных:
productOutputElement.innerHTML = unsafeExample;
```

После демонстрации удалите или закомментируйте этот код.

Безопасный вариант:

```js
productOutputElement.textContent = unsafeExample;
```

Пояснение:

* `innerHTML` воспринимает строку как HTML-разметку;
* `textContent` воспринимает строку как обычный текст;
* поэтому `textContent` безопаснее для пользовательского ввода и данных из внешних источников.

## 14. Типичные ошибки

| Ошибка | Почему возникает | Как исправить |
| --- | --- | --- |
| Студент начал КР №4 с пустой страницы | Не понял связь КР №4 с предыдущими проектами | Перенести основу из `kr3-responsive-shop` |
| Используется Bootstrap-проект без понимания отличий | Студент взял КР №2 как основу | Рекомендуемый вариант — КР №3; Bootstrap допустим только как альтернатива |
| В консоли ошибка `product is not defined` | `main.js` подключён раньше `data.js` | Сначала подключить `data.js`, потом `main.js` |
| JavaScript не выполняется | Неверный путь к файлу | Проверить `src="js/main.js"` |
| Скрипт выполняется раньше HTML | Не используется `defer` | Добавить `defer` к внешним скриптам |
| Используется `var` | Студент копирует старые примеры | Использовать `const` и `let` |
| Функция выводит результат в консоль, но ничего не возвращает | Вместо `return` используется только `console.log` | Добавить `return` |
| Цена превращается в строку слишком рано | Студент смешивает расчёт и форматирование | Сначала считать числа, потом форматировать строку |
| Используется `==` вместо `===` | Не учитывается строгое сравнение | Использовать `===` и `!==` |
| Данные выводятся через `innerHTML` | Студент не различает HTML и текст | Использовать `textContent` для пользовательских данных |
| Код падает на другой странице | В `main.js` ищется элемент, которого нет на этой странице | Проверять найденный элемент через `if` |
| README не обновлён | Студент сделал только код | Добавить описание структуры и выполненных функций |

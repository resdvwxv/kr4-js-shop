### 6. Итоговая логика контрольной работы №4

### 9. Самостоятельные доработки КР №4

Для получения оценки выше 4 баллов студент должен добавить самостоятельные доработки.

Самостоятельная доработка должна быть осмысленной, связанной с интерфейсом интернет-магазина и объяснённой в `README.md`.

Возможные самостоятельные доработки:

| Доработка | Что проверяет |
|---|---|
| Корзина | работа с массивом выбранных товаров |
| Расчёт суммы корзины через `reduce` | расчёты и методы массивов |
| Скидка или промокод | условия, функции, пересчёт суммы |
| Избранное | отдельное состояние интерфейса |
| `localStorage` | сохранение корзины, избранного или темы |
| Пагинация | работа с подмножеством массива |
| Счётчик товаров | обновление состояния интерфейса |
| Пустое состояние каталога | обработка ситуации, когда товаров нет |
| Имитация отправки формы | завершённый пользовательский сценарий |
| Тёмная тема | `classList`, состояние, сохранение выбора |
| Улучшенная карточка товара | дополнительные поля, рейтинг, бейджи, состояние наличия |
| Модальное окно товара | события, доступность, вывод данных |
| Расширенная валидация формы | дополнительные правила без перегруза архитектуры |

Простая замена названий товаров, цветов или текста без расширения JavaScript-логики не считается существенной самостоятельной доработкой.

### 11. Подготовка проекта КР №4 к сдаче

**Этап 1. Проверьте структуру проекта**

Проверьте, что в проекте есть основные страницы:

- `index.html`
- `catalog.html`
- `product.html`
- `order.html`
- `contacts.html`

Если реализована корзина, добавьте:

- `cart.html`

Проверьте папку `js/`:

```text
js/
├── data.js
├── catalog.js
├── validation.js
└── main.js
```

Дополнительные файлы допускаются:

- `cart.js`
- `modal.js`
- `storage.js`

Главное — объяснить назначение каждого файла в `README.md`.

**Этап 2. Проверьте массив товаров**

В `js/data.js` должен быть массив:

```javascript
const products = [
  {
    id: 1,
    title: 'Название товара',
    category: 'category',
    price: 1000,
    isAvailable: true
  }
];
```

Проверьте:

- товаров не менее 8;
- желательно не более 12 для учебной работы;
- у всех товаров одинаковая структура;
- категории совпадают со значениями в фильтре;
- `id` уникальны;
- цены записаны числами, а не строками.

Плохо:

```javascript
price: '1000'
```

Лучше:

```javascript
price: 1000
```

**Этап 3. Проверьте каталог**

На странице `catalog.html` должны работать:

- вывод карточек товаров;
- поиск;
- фильтр;
- сортировка;
- пустое состояние;
- вывод количества найденных товаров.

Проверьте сценарии:

1. Открыть каталог.
2. Убедиться, что товары выводятся.
3. Ввести часть названия товара.
4. Проверить, что список обновился.
5. Выбрать категорию.
6. Проверить, что список обновился.
7. Выбрать сортировку.
8. Проверить порядок товаров.
9. Ввести запрос, по которому ничего не найдено.
10. Проверить сообщение о пустом результате.

**Этап 4. Проверьте форму**

На странице `order.html` должна работать базовая валидация.

Проверьте:

- пустая форма не проходит проверку;
- e-mail проверяется;
- телефон проверяется;
- ошибки выводятся рядом с полями или в понятном блоке;
- сообщения выводятся на страницу;
- не используется `alert()` как основной способ сообщения;
- после корректного заполнения появляется сообщение об успешной подготовке заявки.

Сложная валидация форм не требуется в КР №4. Она будет подробнее рассматриваться в React/Vue-блоке. В КР №4 достаточно показать базовую клиентскую проверку и корректную работу с DOM.

**Этап 5. Проверьте безопасность вывода данных**

Проверьте код проекта.

Для пользовательских данных, данных формы, данных из `localStorage` и будущих API-данных не должно использоваться небезопасное вставление через `innerHTML`.

Рекомендуемый паттерн:

```javascript
const title = document.createElement('h3');
title.textContent = product.title;
```

Или:

```javascript
messageElement.textContent = 'Заявка подготовлена.';
```

Если `innerHTML` используется для статической, полностью контролируемой разметки, студент должен понимать ограничение и уметь объяснить, почему там нет пользовательских данных. В базовом учебном решении лучше обходиться без `innerHTML`.

**Этап 6. Проверьте события**

В проекте должны использоваться обработчики:

```javascript
element.addEventListener('click', handler);
element.addEventListener('input', handler);
element.addEventListener('change', handler);
form.addEventListener('submit', handler);
```

Не рекомендуется использовать inline-обработчики в HTML:

```html
<button onclick="addToCart()">...</button>
```

Правильнее держать поведение в JavaScript-файлах.

### 14. Типичные ошибки при сдаче КР №4

| Ошибка | Почему возникает | Как исправить |
|---|---|---|
| Проект начат с пустой страницы | Не понята связь с предыдущими КР | Создать `kr4-js-shop` на основе интернет-магазина |
| Товаров меньше 8 | Использован только учебный массив из методички | Расширить массив до 8–12 товаров |
| Карточки написаны вручную в HTML | Не выполнена генерация через JS | Создавать карточки через `createElement()` |
| Поиск работает только после перезагрузки | Нет обработчика `input` | Подключить `addEventListener('input', ...)` |
| Фильтр не работает | Значения категорий не совпадают | Сверить `product.category` и `option value` |
| Сортировка ломает исходный порядок | `sort()` применён к исходному массиву | Сортировать копию массива |
| Ошибки формы выводятся через `alert()` | Скопирован старый подход | Выводить сообщения в DOM через `textContent` |
| Используется `innerHTML` для пользовательских данных | Не учтена безопасность | Использовать `textContent`, `createElement`, `append` |
| Скрипт падает на другой странице | Код ищет элементы, которых там нет | Добавить проверки существования элементов |
| README не описывает JS-логику | Документация не обновлена | Добавить описание файлов, функций и доработок |
| Студент не может объяснить код | Код скопирован без понимания | Разобрать функции и сценарии работы |
